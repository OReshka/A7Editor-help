Релиз — «запечённый» снимок конфигурации: точные версии всех пакетов,
контрольные суммы и собственный номер версии. Релиз тестируется и
продвигается **целиком** — пакеты связаны друг с другом.

## Путь релиза

[[steps]]
1. **Собрать** — тестировщик или девопс фиксирует набор версий пакетов
   и запекает `configuration.yaml` с `type: release`.
2. **Проверить** — тестировщик прогоняет релиз и ставит **флаг ревью**:
   вердикт от красного до зелёного.
3. **Продвинуть** — девопс ставит **канал** (qa / stable / production):
   «эту версию сейчас брать».
4. Метки автоматически расставляются на версии всех пакетов,
   вошедших в релиз, — команда видит вердикты по конкретным версиям.
[[/steps]]

## Каналы и флаги — две разные метки

|  | Канал | Флаг ревью |
|---|---|---|
| Смысл | «какую версию брать» | «вердикт проверки» |
| Значения | qa / stable / production | 🔴 🟡 🔵 🟢 |
| Кто ставит | девопс | тестировщик |
| Механика | передвигаемый git-тег | запись в релиз + git-тег |

Обе метки ставятся на релизную конфигурацию и наследуются версиями
входящих пакетов. Благодаря каналам разработчик может затребовать
в своём шаблоне `require: { channel: stable }` — и не тянуть
непроверенные промежуточные версии.

> [!NOTE]
> Релиз — это тот же `configuration.yaml`, только `type: release`.
> Отдельного формата файла у релиза нет — см. «configuration.yaml».
