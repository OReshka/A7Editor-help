Изменения редактора по версиям, от новых к старым. После обновления
редактор один раз сам показывает раздел своей новой версии в окне
«Что нового».

> [!TIP]
> Окно можно отключить галочкой «Больше не показывать» или в
> «Настройки → Общие → „Что нового“ после обновления». Там же его
> можно включить обратно.

## 1.7.0

- **GitLab рядом с GitHub.** Редактор работает с несколькими git-серверами
  сразу. Токен для каждого сервера задаётся в «Настройки → Git → Токены
  серверов» и работает и в режиме SSH, и в режиме HTTPS. Как получить
  токен — в статье о настройке Git.
- **Переезд репозиториев.** Если в манифесте конфигурации у пакета появился
  адрес на другом сервере с тем же именем репозитория, редактор сам
  переключит `origin` клона при открытии конфигурации и при массовом pull.
  Клон переключается, только если новый адрес отвечает. Иначе он остаётся
  на старом сервере, а в журнале появляется предупреждение. Другие проекты
  и форки редактор не трогает.
- **Блоки виджетов WD.** `a7dbojs` принимает вложенные виджеты сервера v26,
  например `body: Circle { radius: this.size / 2; }`. На пакеты без блоков
  это не влияет: их `.dbo` не меняется.
- **Ревью типов.**
  - Удаление члена больше не падает с ошибкой «member not found».
  - Решения применяются по uid и целиком: при ошибке файлы возвращаются
    в исходное состояние.
  - Если на вопрос о члене нет ответа, изменения не применяются.
  - При переносе поля в родителя его uid сохраняется.
  - При смене `extends` проверяются и наследники, а проблема наследника
    показывается один раз, в его файле.
- **Переименование типа.** Обновляются все ссылки на тип во всех пакетах
  конфигурации, `.dbo` и `packet.yaml`. Открытые документы перед этим
  сохраняются.

- **Защита клонов.** Папка пакета с коммитами, но без `packet.yaml` больше
  не удаляется и не скачивается заново. Редактор оставляет её как есть и
  сообщает об ошибке.

## 1.6.0

- **Пуш наследников на сервер A7/19.** Сервер A7/19 не обновляет
  наследников, когда меняется базовый тип. Теперь пуш на сервер A7/19
  отправляет вместе с типом всех его наследников из всех пакетов
  конфигурации, от родителя к потомку. Пуш типа отправляет тип и
  наследников одним запросом. При пуше пакета наследники из других
  пакетов идут следом, отдельными строками в окне статуса пуша.
- Предки не добавляются. Серверу v26 наследники не отправляются: он
  пересобирает их сам.
- Выключатель — «Настройки → Общие → Push → Пушить тип вместе с
  наследниками». По умолчанию он включён.

> [!WARNING]
> Если перенести поле между родителем и наследником, значения этого
> поля на сервере A7/19 потеряются. Если у какого-то наследника нет
> uid (нет `.dbo`), пуш не выполнится, а в сообщении будет назван
> этот тип.

- **Окно «Что нового».** После обновления редактор один раз показывает,
  что изменилось в новой версии. Текст берётся из этой статьи справки,
  поэтому без сети окно появится при следующем запуске. Вся история
  изменений — «Справка → Что нового».
