`configuration.yaml` — манифест конфигурации: какие пакеты входят и
откуда их брать. У файла есть **тип**, и он определяет роль файла.

## type: developer — редактируемый шаблон

Рабочий вход разработчика и тестировщика. Содержит *требования*
к пакетам, а не зафиксированные версии:

```yaml
name: SmartHome
type: developer
packets:
  Timer:
    require:
      version: "1.8"        # либо channel: stable
    source: { git: '…', subpath: ./packets/Timer }
```

- `require.version` — мажор (`1`), мажор+минор (`1.8`) или полная (`1.8.2`).
- `require.channel` — взять текущую версию канала (`stable`, `production`);
  взаимоисключимо с `version`.
- `source` — откуда брать пакет: git-репозиторий или путь.

## type: release — запечённый артефакт

Генерируется командой «Сделать релиз» и **не редактируется**:

```yaml
name: SmartHome
type: release
version: "2026.1.0"          # собственная версия релиза
generatedAt: "2026-06-03T18:00:00Z"
packets:
  Timer:
    version: "1.8.2"         # точная версия пакета
    hash: "0011aabb…"        # sha256 содержимого
    source: { git: '…', ref: '<коммит>', subpath: ./packets/Timer }
```

Каждый пакет зафиксирован на конкретном коммите с контрольной суммой —
релиз воспроизводим в любой момент.

> [!NOTE]
> Редактор не показывает `configuration.yaml` как файл — вы меняете его
> косвенно, через дерево проекта, и манифест всегда остаётся согласован
> с файлами на диске.
